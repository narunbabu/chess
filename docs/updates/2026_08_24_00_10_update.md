# 2026-08-24 — Android: move failure, synthetic-player copy, lobby count

Found by driving the app on a Play-Store emulator over adb against production,
not by reading code. All three were reproduced on-device and re-verified there.

## 1. "Failed to send move" on every synthetic-opponent move

Reproduced on game 2021. The 422 body:

```json
{"errors":{"move.san":["required"],"move.uci":["required"],
 "move.is_mate_hint":["required"],"move.is_check":["required"],
 "move.is_stalemate":["required"]}}
```

Backend commit `2c4b08d` relaxes exactly these five to `nullable` — and it is
**not on `master`**, so it was never deployed. Proof without touching the VPS:
`/api/v1/user/progress` (added by the equally undeployed `95b528e`) returns 404
on prod, while a master-side route returns 401.

**Fixed client-side rather than waiting on a deploy.** `onPlayerMove` now sends
the same metadata the web client has always sent (`PlayMultiplayer.js:4813`), so
the native client satisfies the deployed validation *and* the relaxed one:

- `san` — computed once post-move and reused for the local record
- `uci` — `from + to + promotion`
- `is_check` / `is_mate_hint` / `is_stalemate` — snapshotted with `san` before
  the request coroutine launches, so they describe *this* move even if state
  advances first

Re-tested: `POST .../move` → **200**, opponent replied, move list `1. e4 e6`,
zero `Failed to send move` in logcat.

Two latent instances of the same bug fixed in `companionPlayOneMove`:
- its fallback to the regular move API sent bare `from/to/promotion`, so every
  fallback 422'd and the companion move was silently lost
- `is_mate_hint` was hardcoded `false` — a companion move delivering mate told
  the server the game was still running

## 2. Synthetic players are opponents, not "bots"

Per owner direction, players should pick opponents by rating without being told
which are synthetic. `isSynthetic` still drives *behaviour* (instant start vs
invitation), just never the copy.

- `LobbyScreen` — removed the `BOT` badge from the player row
- `LobbyViewModel` — name fallback `"Bot"` → `"Player"`
- `PlayComputerScreen` — *Play a bot* → *Choose an opponent*

Left alone deliberately: the Terms of Service clause about using engines/bots to
cheat (a real, different meaning), and the `bottts` DiceBear avatar style id.

## 3. Lobby said "0 online" above nine playable opponents

The badge read `onlineCount`, from an endpoint that counts only real humans. It
now counts what the Players tab actually lists — verified as *40 online*.
