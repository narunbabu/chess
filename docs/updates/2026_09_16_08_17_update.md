# Multiplayer Best-move budget accounting (Module 4 parity follow-up)

Date: 2026-09-16

## What was delivered

The casual/learning multiplayer Best toggle now has the same
`bestMoveBudget` / `undoChancesRemaining` accounting the learning computer
mode has, on both clients, uncommitted.

Design (one invariant, both platforms):
`budget = server remaining (undo_<colour>_remaining, fallback 9) − number of
MY moves that carry a persisted `best-move` marker`.

- Best draws from the SAME shared pool as takebacks; a reveal is charged one
  chance, refused once the pool is empty, and re-revealing the same position
  is free (`bestChargedFen` on Android; CCTPanel's per-position charge on web).
- A move played while the paid reveal is showing persists a `best-move`
  marker in the move's `learning_help` array (sent in the move payload, stored
  server-side) — the same marker set the Game Review lifeline summary reads,
  so the lifeline summary and the budget stay correct across reload. The move
  itself does not charge again; the reveal clears because the position changed.
- Reload/undo-resync rebuilds the budget from the persisted markers, so a
  reload neither refunds nor double-charges a spend.

## Changes

- `chess-frontend/src/utils/multiplayerBestBudget.js` (new) —
  `countBestMoveSpend(moves, myColor)` (accepts raw server moves, compact
  history entries and decoded records) and `budgetedUndoChances({...})`
  (rated → 0; clamps at 0; fallback when the server predates the columns).
- `chess-frontend/src/utils/__tests__/multiplayerBestBudget.test.js` (new) —
  12 tests over every persisted marker shape and the reload seeding.
- `chess-frontend/src/components/play/PlayMultiplayer.js` — the load path
  seeds `undoChancesRemaining` via `budgetedUndoChances`; the takeback-resync
  path recomputes it as server remaining minus `countBestMoveSpend` over the
  kept history; the Best toggle charges `consumeMultiplayerBestHelp` from the
  shared pool and is refused when empty.
- `chess99-android/.../PlayMultiplayerViewModel.kt` — `bestMoveSpend()` over
  `GameMoveRecord.lifelines`; load and authoritative-takeback paths subtract
  it from the server count; `setCctHintLevel(2)` charges one shared chance
  (`bestChargedFen` guards double-charging) and shows
  `mp_best_no_chances` when the pool is empty; the player's move captures the
  marker into `learning_help` in the payload and the local record without a
  second charge; any position change (own move, opponent move, takeback)
  clears the paid reveal.
- `chess99-android/.../PlayMultiplayerScreen.kt` — the Best control is
  enabled from `undoChancesRemaining` (`canUseBestMoves`), so the UI gates on
  the same pool the takeback button shows.
- Fix during verification: `handleOpponentMove`'s desync fallback (local
  `game.move` fails, position resynced from the server FEN) returned without
  clearing the paid Best reveal, leaving a reveal for a position that no
  longer existed. It now clears the reveal when the resynced FEN differs from
  the local one — the new `opponent move clears best without charging` JVM
  test covers exactly this path.
- `chess99-android/.../PlayMultiplayerBestBudgetTest.kt` (new) — 9 JVM tests:
  charge on toggle, same-position retoggle free, empty-pool refusal with copy,
  rated never enables, move-with-best persists the marker without a second
  charge, opponent move clears without charging, reload subtracts persisted
  markers, takeback resync keeps subtracting the kept spend, and
  `bestMoveSpend` colour filtering.
