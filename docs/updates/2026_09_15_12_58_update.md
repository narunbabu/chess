# 2026-09-15 12:58 — fix(client): paused-game resume-status poll URL

## Problem
The WebSocket-disconnected fallback poll in `PlayMultiplayer.js` (the effect that
starts polling when `gameInfo.status === 'paused'`) fetched
`${BACKEND_URL}/games/${gameId}/resume-status`. No such route exists, so every tick
404'd (seen in the 12:50 live check; pre-existing). The route is registered only under
the `websocket` prefix (`routes/api.php:236` group → `api/websocket/games/{gameId}/resume-status`,
plus `api/v1/websocket/...`), which the other three resume-status callers in the file
already use.

## Change
- `chess-frontend/src/components/play/PlayMultiplayer.js`
  - Poll now fetches `${BACKEND_URL}/websocket/games/${gameId}/resume-status`.
    `WebSocketController@getResumeStatus` returns `pending`, `type`, `requested_by_id`,
    `requesting_user`, `opponent_name`, `expires_at` — exactly the fields the poll reads.
  - The 2-minute `cleanupTimer` is now hoisted and cleared in the effect cleanup. Before,
    it was a block-scoped `const` that was never cleared, so each re-run of the effect
    left a stray timeout behind.

## Verification
- `php artisan route:list --path=resume-status` → only the two `websocket` routes.
- No remaining `${BACKEND_URL}/games/${gameId}/resume-status` callers in `src/`.
- `pnpm exec eslint src/components/play/PlayMultiplayer.js` → 0 errors, 76 pre-existing warnings.
- `pnpm test --watchAll=false` → 13 suites / 110 tests passed.
- `pnpm build` → compiled.
- **Not live-checked in a browser**: the poll only runs while the WebSocket is disconnected
  on a paused game, which was not reproduced this session.

## Rollback
Revert the single-file change in `PlayMultiplayer.js`. Not committed, pushed or deployed.
