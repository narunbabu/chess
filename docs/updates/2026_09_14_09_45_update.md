## Why nothing was changed

- `git push` is forbidden by the worker session rules.
- `gh workflow disable` / `enable` change the state of the owner's GitHub repository. That is
  an account change, which the worker rules also forbid.
- The rules do not allow a commit or history rewrite either, unless the task asks for one. The
  task gives amending as an alternative for the owner, but it would not work as written. See below.

## Correction: amending `[skip ci]` into `d48a4b4` does not skip the deploy

GitHub decides whether to skip a `push` run from the **head** commit of the push. Local
`master` is `daf9405` → `d48a4b4` → `c9db620`, and `c9db620` is the head. Putting `[skip ci]`
into `d48a4b4` also means rebasing `c9db620` on top of it, and `c9db620` would still have no
`[skip ci]`, so `deploy.yml` would still start. (This comes from GitHub's documented skip-ci
rule. It was not tested live, because testing it needs a push.) Two things work:

1. the disable → push → enable sequence, or
2. a `[skip ci]` in the **head** commit: either reword `c9db620`
   (`git commit --amend`, safe because it is unpushed) or add an empty commit on top.
