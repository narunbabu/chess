## Defects found and fixed

1. **`GameController::publicShow` 404'd for every game — the public replay
   feature was dead on both clients.** The guard was
   `$game->status !== 'completed' && !== 'ended'`. `status` is an accessor over
   the `game_statuses` lookup (`create_games_table` seeds
   waiting/active/finished/aborted/paused); `completed` is only a *write-side*
   alias that `GameStatus::fromLegacy` maps onto `finished`, and `ended` is not
   a code at all. So the guard matched nothing. Android moving onto the public
   endpoint would have achieved nothing without this. Now compares with
   `GameStatusEnum::FINISHED`. Web `GameReplayPage.js:78` uses the same route
   and was equally broken.

2. **The daily solver auto-played the opponent.** A daily solution is a list of
   the player's own moves (web: `DailyChallengePage.js:126-140` compares the
   Nth move played with `solution[N]`), but Android ran it through the generic
   UCI puzzle solver, which treats entry 1 as the opponent's reply. A
   multi-move line would have submitted a short solution — which
   `submitDailyChallenge` rejects on `count($solution) === count($correct)` —
   and the SAN→UCI pre-conversion returned null for such a line, dropping the
   challenge from the screen entirely. The daily branch now matches SAN
   directly, with the backend's own normalization (`+`/`#` stripped,
   case-insensitive), and never auto-plays. All seeded solutions are currently
   one move, so this was latent.

3. **Submitted SAN was generated on the wrong board.** `Move.san()`
   disambiguates against `game.legalMoves()`; it was called after the move had
   been made, so the candidates were the *opponent's* and a bogus file/rank
   prefix could be prepended ("Rda8" for "Ra8"), which the server compares
   literally. SAN is now read off a pre-move board, in both solver branches.

4. **A failed bundled-asset read took the daily challenge down with it.**
   `loadBundledPuzzles()` threw inside the shared try, so nothing reached the
   screen. Bundled loading now degrades to an empty list.

5. Minor: daily challenges show their written `challenge_data.hints` rather
   than a synthesized "try moving from e2"; re-solving an already-completed
   challenge says so rather than claiming a fresh save
   (`daily_review_already_completed`).
