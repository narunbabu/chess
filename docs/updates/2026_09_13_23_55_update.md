# 2026-09-13 23:55 — check_backend_health.ps1 expects the real statuses

## Problem
`chess99-android/scripts/check_backend_health.ps1` probed
`/api/v1/synthetic-players` as though it should answer 200. The route is
registered inside the `Route::middleware('auth:sanctum')` group in
`chess-backend/routes/api_v1.php`, so an unauthenticated probe answers
**401** `{"error":"Unauthenticated",...}`, which the script printed as `ERR`.
The script also never checked `/api/v1/health`, although `CLAUDE.md`/`AGENTS.md`
say it does. It always exited 0, so it could not serve as a gate.

## Change
- Each target now declares its expected status: `/up` 200,
  `/api/v1/health` 200 with JSON `status: "healthy"`,
  `/api/v1/synthetic-players` **401**, `chess99.com` 200.
- A 401 on synthetic-players shows that the API router and the Sanctum middleware
  are up. A 200 there would mean the route lost its auth, so the script fails on it.
- Handles the 4xx exception from `Invoke-WebRequest` in both Windows PowerShell 5.1 and PowerShell 7.
- Exit 0 = pass, 1 = fail (same contract as `check_assetlinks.ps1`).

## Verification (Windows PowerShell 5.1, against production)
- `powershell.exe -File scripts/check_backend_health.ps1` →
  `/up` 200, `/api/v1/health` 200, `synthetic-players` 401, `chess99.com` 200,
  `PASS`, exit 0.
- Negative test: a temp copy that expects 200 from synthetic-players → `FAIL ... HTTP 401, expected 200`,
  exit 1. The temp copy was deleted afterwards.
- PowerShell 7 (`pwsh`) is not installed on this machine, so the PS7 branch was not run.

No backend or app code changed. Nothing was deployed.
