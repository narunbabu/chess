## Hazard found in step 1, and fixed in the notes
`git checkout --` restores the last tracked `packages.php`
(`d48a4b4^`), which lists dev-only packages (`laravel/pail`,
`laravel/sail`, `nunomaduro/collision`; all in `require-dev`). Production is
installed with `composer install --no-dev`. Normally the pull deletes the
file right away and Laravel rebuilds it. If the pull **fails** after the
checkout (other local changes, network, auth), the restored manifest stays
live, pointing at provider classes that are not installed.

Local reproduction (files backed up and restored afterwards):
- Wrote the tracked manifest with `PailServiceProvider` renamed to a class that
  does not exist, and deleted `services.php`.
- `php artisan --version` → error in `ProviderRepository.php line 205`
  (provider class not found), **rc=1**.
- Restored the backups: `cmp` identical for both files, `php artisan --version`
  → Laravel 12.31.1, rc=0, `git status -- bootstrap/cache` clean.

`scripts/deploy-notes.md` step 1 now reads:

```bash
git checkout -- chess-backend/bootstrap/cache/packages.php chess-backend/bootstrap/cache/services.php
git pull origin master || (cd chess-backend && php artisan package:discover)
```

- A failed pull rebuilds the manifest from the vendor tree that is actually
  installed.
- It is safe to repeat. After the untracking lands, the checkout only prints
  `pathspec did not match` and the pull still runs (`;`-style sequencing, not
  `&&`).
- CI (`deploy.yml`: `git reset --hard origin/master`) does not need the step.

This is a documentation-only change. It is not committed, and it sits in the same
uncommitted `deploy-notes.md` diff as the earlier sudoers-state paragraph.
