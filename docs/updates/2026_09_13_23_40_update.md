## Takeback smoke

New script: `chess-frontend/scripts/smoke-takeback-live.cjs` (Node, uses the
frontend's `ws`; Reverb key read from `chess-frontend/.env.production`). It speaks
the Pusher protocol directly to `wss://api.chess99.com`, authorises
`private-game.{id}` through `/api/websocket/broadcasting/auth`, and resigns every
casual game it creates (casual games skip the rating update).

```
CHESS99_TEST_EMAIL=... CHESS99_TEST_PASSWORD=... node scripts/smoke-takeback-live.cjs synthetic
```

Account: the designated test account (user 8). Game 2038 vs synthetic "Riya First Moves", casual.

Gotcha found: `/synthetic-players` exists only in `routes/api_v1.php`, so it is

### Two-client (pair) leg — written, NOT run

It needs a second production account, and only one test credential exists.
Guessing passwords for other real accounts, or registering one on production,
was out of scope for an unattended run. The leg covers two sockets: request, then
the opponent's socket receives `game.undo.request`, then accept, then both sockets
receive `game.undo.accepted` and the board resets; then request, decline, and the
requester receives `game.undo.declined` with the position kept. Without
`CHESS99_SMOKE_B_EMAIL`/`CHESS99_SMOKE_B_PASSWORD` it prints SKIP and exits 2
(checked). Note that `POST /games` counts against the free-plan daily online-game
quota for account A.
