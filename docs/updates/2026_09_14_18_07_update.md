# 2026-09-14 18:07 — Android Home "Couldn't check for games to resume" root cause

Follow-up to item (a) in docs/updates/2026_09_14_17_55_update.md.

## Finding

Not an emulator timeout. The local serve log shows both Home refresh rounds after
leaving game 463 (17:51:06 and 17:51:08) finished in about 1 s or less. The second
round reached `lobby/players`, so it completed and published its result.

The cause is a response-shape mismatch:

- `GameController::unfinishedGames` ends with `return response()->json($games)` on a
  Collection. The body is a **top-level JSON array** (`[]` or `[{...}]`). The web
  client reads it that way (`unfinishedGameService.js`: `Array.isArray(response.data)`).
- Android declared `GameApi.getUnfinishedGames(): Response<JsonObject>`. Gson's
  converter throws `JsonSyntaxException` ("Expected a JsonObject but was JsonArray")
  before any parsing runs.
- `HomeViewModel.loadUnfinishedGames` wraps the call in `runCatching`, so this showed as
  a failure. `applyResumeLoad` fails the whole resume load, and Home showed the banner.
  This happens on **every** signed-in Home load, not only after leaving a game. The
  device check first saw Home right after leaving.
- `DashboardViewModel.loadUnfinishedGames` had the same bug. It caught the exception
  and only logged it, so the Dashboard unfinished list was always silently empty.
- The HomeViewModel unit tests stubbed `{"games": []}`, a shape the backend never
  sends, so they could not catch this.

## Fix (Android only; backend contract unchanged because web depends on it)

- `GameApi.getUnfinishedGames()` now returns `Response<JsonElement>`.
- New `JsonElement?.arrOrField(vararg keys)` in `JsonSafe.kt`: a bare array, or the
  first wrapping key that holds an array.
- Home and Dashboard both use `body.arrOrField("games", "data")`.
- Tests:
  - HomeViewModelTest stubs now use the real bare-array shape.
  - New regression test: an array body loads cards (dedup with active, colour) and sets
    no resume error.
  - JsonSafeTest: a helper test, plus a test showing Retrofit's `GsonConverterFactory`
    rejects `[]` as `JsonObject` and accepts it as `JsonElement`.
