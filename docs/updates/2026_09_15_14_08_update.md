# Casual bot resume on Android open

## Outcome

Casual games against computer or synthetic opponents no longer strand the player behind the Request Resume overlay after Android Leave. The Android view model requests resume while opening a paused casual bot game, and the backend treats the human's request as an automatic bot acceptance.

## Changes

- Android `PlayMultiplayerViewModel` detects a paused casual computer game during `loadGame`, calls the authenticated resume-request endpoint, and treats a successful response as active before starting the timer and synthetic opponent loop.
- Android navigation pause now sends the current white/black clocks and `paused_reason` in the request body.
- `GameRoomService::requestResume` auto-resumes casual games with `computer_player_id` or `synthetic_player_id`, closes any legacy pending invitation, and leaves human-vs-human invitations unchanged.
- `resumeGameFromInactivity` now falls back from missing pause clocks to remaining clocks or the configured time control, protecting games paused by older Android clients.
- `Game::$fillable`/casts now include the restored remaining clocks and `last_move_time`, so resume state is persisted.
