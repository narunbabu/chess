workflow works again. **The secret itself was not changed.** Generating a key,

## Diagnosis

The action gets as far as offering `publickey`, which means the secret parses
as a valid private key. A malformed secret fails earlier, with a parse error.
The secrets did not change between the green December run and the red
February run, so the server changed. Either the matching public key was removed
from `SERVER_USER`'s `authorized_keys`, or that account (probably `root`, given
`COMPOSER_ALLOW_SUPERUSER` and the sudo-less commands in the committed workflow)
lost SSH login. Manual deploys since then have used `narun` with
`~/.ssh/narun_vps_ed25519`. The VPS was not inspected, because that needs the
key zone.
