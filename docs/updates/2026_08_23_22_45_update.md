# 2026-08-23 — Google Sign-In decoupled from Firebase (Android)

## What changed

`chess99-android/app/build.gradle.kts` only. No Kotlin source, no resources.

1. `GOOGLE_SIGN_IN_ENABLED` no longer depends on `hasProductionFirebaseConfig`:

   ```kotlin
   // before
   (hasProductionFirebaseConfig && hasValidGoogleServerClientId).toString()
   // after
   hasValidGoogleServerClientId.toString()
   ```

2. Two checks removed from `verifyReleaseConfiguration` — the ones requiring
   `google-services.json` to carry a non-empty `oauth_client` array and to
   contain `GOOGLE_SERVER_CLIENT_ID`. Both encoded the assumption that Google
   Sign-In is registered through Firebase.

## Why

Google Sign-In here runs through **Credential Manager**, which takes the web
OAuth client ID as an explicit parameter — `GoogleSignInHelper.kt` passes
`BuildConfig.GOOGLE_SERVER_CLIENT_ID` into `GetGoogleIdOption.setServerClientId`.
It never reads `google-services.json`.

Evidence: the app source has **zero** references to `default_web_client_id`,
`GoogleSignInOptions`, `requestIdToken` or `FirebaseApp`. The only Firebase
consumer in the codebase is `Chess99FirebaseMessagingService` — push
notifications, an unrelated feature. No test asserted the old coupling.

The practical effect of the old gate: because `app/google-services.json` is
still the placeholder (`project_id: chess99-placeholder`), the flag was `false`,
so `LoginScreen.kt:193` and `RegisterScreen.kt:309` hid the Google button and
`GoogleSignInHelper` refused to launch — on builds that were perfectly capable
of signing in.

The placeholder `google-services.json` stays in place: the `google-services`
Gradle plugin fails the build if the file is absent, and the placeholder
satisfies it. The Firebase checks that remain in `verifyReleaseConfiguration`
are now strictly about FCM / Crashlytics / Analytics being inert.

## Where registration actually lives

Google Cloud Console → APIs & Services → Credentials, in the **same project as
the web client** (`289055198367`), since the ID token's `aud` must be the web
client — `AuthController::googleMobileLogin` compares it against
`config('services.google.client_id')`, and the two already match.

An **Android** OAuth client is required, carrying:

| Field | Value |
|---|---|
| Package name | `com.chess99.app` |
| SHA-1 (debug, today's APK) | `D5:DF:BD:6C:3A:08:BB:72:5E:75:AD:FB:90:A1:8B:7A:9C:BD:82:31` |
| SHA-1 (upload key) | `39:87:25:23:36:1A:E8:75:4F:84:B4:7B:8B:9E:40:69:4C:CD:1B:C7` |

A GCP Android client holds exactly one package+SHA-1 pair, so each fingerprint
needs its own client (debug, upload, and later Play App Signing). The Android
client ID is never referenced by the app — it only authorises this
package+signature to request tokens for the web client. This is the difference
from Firebase, whose "add fingerprint" button creates these clients for you.
