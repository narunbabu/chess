## Investigation before speccing (4 parallel deep-dives)
- **Stockfish**: bridge extracts `assets/stockfish` → `filesDir` and execs —
  but API 29+ blocks exec from app storage (W^X). Correct pattern:
  `libstockfish.so` in `jniLibs/<abi>/` + exec from `nativeLibraryDir`.
  NDK 29.0.14206865 is installed locally.
- **Data layer**: root-caused all five release breaks — Dashboard/Referrals
  spawn 5 fire-and-forget child loaders whose catch blocks never clear
  `isLoading`; GameHistory/MyPlan render `${e.message}` (obfuscated class
  names) to users; Profile Stats has no load state at all.
- **WebViews/Learn**: privacy/terms/ebook URLs serve the SPA shell (curl-
  verified) which fails inside WebView; web legal pages are self-contained JSX
  (219/197 lines) → portable natively. Tutorial API wraps everything in
  `{success, data}` envelope + `data.stats` nesting that LearnViewModel never
  unwraps → fake-empty Learn.
- **Puzzle data (MAJOR CORRECTION)**: the web is NOT broken — TacticalTrainer.js
  has `normalizePuzzle()` (applies the Lichess setup ply at load). Android
  never ported it. Fix = 25-line Kotlin port, NOT a 2×2,500-puzzle regeneration
  (which would double-apply the setup ply on web and break it). Generator bug
  documented at `chess-backend/database/puzzles_data_download_lichess.js:32-44`.
  Also found: canonical referral route is `/r/{code}` (App.js:178); Android
  builds `/join/{code}` — wrong path, zero attribution.
