# 2026-08-21 — Android release backlog: the reachable half

Unattended pass over the ten open items in `STATUS.md`. Four are blocked on
things an agent cannot reach (a physical phone, the Firebase console, the Play
Console, a production deploy); this covers what was actually done.

## Closed

### Deploy health check (`/health` → `/up`)
`https://api.chess99.com/health` 404s. Laravel's health endpoint is `/up`
(`chess-backend/bootstrap/app.php:13`); the richer JSON probe the native apps
use is `/api/v1/health` (`routes/api_v1.php:44`). Corrected in `CLAUDE.md`,
`AGENTS.md` and `docs/project-notes/chess-web.md`, all three of which carried
the same wrong command.

### Ambassador adult gate — and the gap behind it
The gate itself already existed: `EnsureAdult` middleware, registered as
`adult` in `bootstrap/app.php`, applied to the `ambassador` group in both
`routes/api.php` and `routes/api_v1.php`, failing closed on an unknown
birthday.

What did not exist: `POST /api/ambassador/payout-request` and
`GET /api/ambassador/payout-requests`. Only the `/api/v1` copies were
registered, but `chess-frontend/src/pages/AmbassadorDashboard.js` calls them
under `BACKEND_URL` (`https://api.chess99.com/api`) — so submitting a payout
request from the web dashboard was hitting a 404. Both routes added inside the
gated group. `AmbassadorAdultGateTest` grew from 10 to 14 tests covering the
new routes for minors, unknown-birthday users and adults.

### Board piece-move animation
`ChessBoardView`'s doc comment claimed "animated piece sliding (via
recomposition)"; there was none — pieces teleported. Now the piece that just
moved slides from `lastMoveFrom` to `lastMoveTo` over 180 ms
(`FastOutSlowInEasing`), and castling slides the rook alongside the king.

Suppressed for drag-and-drop: the player has already dragged the piece to the
destination, so replaying the slide reads as a rewind. `onDragEnd` records the
squares it produced and the animation driver skips that move.

The geometry — orientation mapping and the castling rook derivation — is split
into `BoardGeometry`, a pure object with no Compose or Android types, so it is
unit-testable on the JVM. `BoardGeometryTest` adds 10 tests, including that a
queen sweeping e1–g1 does not drag the h1 rook with it.

## Partly done

### Lint / accessibility / localisation backlog
118 warnings → 72. Every remaining warning is either "a newer version of X is
available" (63 `GradleDependency` + 3 `AndroidGradlePluginVersion`) or one
`CredentialManagerSignInWithGoogle` that appears to be a false positive — the
file does reference `GoogleIdTokenCredential`, which is what the check asks
for. Dependency bumps were deliberately left alone this close to a release
build.

Fixed:

| Warning | Count | Change |
|---|---|---|
| `UseKtx` | 23 | `prefs.edit { }`, `String.toUri()`, `createBitmap()` |
| `IntentFilterUniqueDataAttributes` | 14 | Split the App Links `<data>` tags — scheme and host declared once, one tag per path. Merged manifest verified: same 14 paths |
| `DefaultLocale` | 6 | `String.format(Locale.getDefault(), …)` on user-visible numbers |
| `AndroidGradlePluginVersion` (partial) | — | n/a |
| `ObsoleteSdkInt` | 1 | `mipmap-anydpi-v26` → `mipmap-anydpi` (minSdk is 26) |
| `DataExtractionRules` | 1 | Added `data_extraction_rules.xml` + `backup_rules.xml`, both full opt-out — the app's shared prefs hold the Sanctum token and a child's profile, so neither cloud backup nor device transfer should carry them |
| `CredentialManagerMisuse` | 1 | `NoCredentialException` now has its own `GoogleSignInResult.NoCredential` branch with "no Google account on this device" copy, instead of collapsing into the generic failure text |

Also, though not lint-reported:

- 15 deprecated `Icons.Filled.*` uses migrated to `Icons.AutoMirrored.Filled.*`
  (`TrendingUp`, `ArrowForward`, `Undo`, `NavigateBefore/Next`, `ShowChart`,
  `MenuBook`, `Chat`, …). The manifest sets `supportsRtl="true"`, so these
  were silently pointing the wrong way in RTL locales.
- Deprecated `Modifier.menuAnchor()` → `menuAnchor(MenuAnchorType.PrimaryNotEditable)`.
- The three password-visibility toggles that had `contentDescription = null`
  (register, reset ×2) are now labelled — they were unreachable buttons under
  TalkBack. `LoginScreen`'s already-present labels moved to resources.
- The board is a bare `Canvas`, so TalkBack had nothing at all to read. It now
  carries a `contentDescription` announcing the last move, side to move and
  check.

### UI copy → `strings.xml`
`strings.xml` had 4 entries (app name + Facebook SDK config); everything else
was a Kotlin literal. The full pre-account surface is now extracted —
`LoginScreen`, `RegisterScreen`, `ForgotPasswordScreen`, `ResetPasswordScreen`,
`SkillAssessmentScreen` and the onboarding pager (~60 strings), establishing
the `auth_*` / `onboarding_*` / `a11y_*` / `action_*` naming convention.

`onboardingPages` was a top-level `val` holding literals, which cannot call
`stringResource()`; it now holds `@StringRes Int`s resolved at render time.

Roughly 660 literal sites remain across ~55 screens. `ErrorCopy.kt` and
`authErrorCopy` need `@ApplicationContext` injection before ViewModel-side copy
can move, so the "No Google account on this device" string was left as a
literal alongside its neighbours rather than half-migrating that layer.

### App Links (`assetlinks.json`)
Deploying is out of scope for an unattended run, but the diagnosis is not.
`https://chess99.com/.well-known/assetlinks.json` still answers 200 with
`text/html` — the SPA `index.html` fallback. The file *is* present in
`chess-frontend/build/.well-known/`, so this is a server-side copy or nginx
`location` problem, not a build problem.

`chess99-android/scripts/check_assetlinks.ps1` was a printer, not a check. It
now asserts `Content-Type: application/json`, that the body parses, that it
declares an `android_app` target for `com.chess99.app`, and that at least one
SHA-256 fingerprint is listed — and exits non-zero. Run against production it
correctly fails today. The deploy procedure in `CLAUDE.md` / `AGENTS.md` gained
an App Links step covering the dot-directory and the
`location ~ /\.(?!well-known)` nginx caveat.
