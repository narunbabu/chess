## Task

"Decide and fix: Android 'Leave game' leaves casual bot game ongoing though dialog
says it counts as a loss." Follow-up to the 18:31 decision note.

## Decision (refines 18:31 follow-up #1)

| Game | Leave does server-side | Dialog copy |
|---|---|---|
| Rated (human or bot) | Resign: bot via `completeGame` (applies synthetic Elo), human via `resignGame` | "This is a rated game. If you leave now, you resign and it counts as a loss." |
| Casual vs human | `pauseGame` over the socket service (web "Pause Game & Navigate" parity) | "Your game will be paused. You can resume it from Home within an hour." |
| Casual vs bot | Nothing. Game stays `active` | "Your game stays open. You can continue it later from Home." |

The 18:31 note proposed `pause-navigation` for casual bot games too. That is wrong
on Android and was **not** done:

- A paused game opens in `PlayMultiplayerScreen` as `MultiplayerPhase.PAUSED`, whose
  only action is `requestResume` (`GameRoomService::requestResume`) — a pending
  request the opponent must accept. No code answers it for a synthetic player
  (unlike undo, which is auto-accepted at `GameRoomService.php:2683`). A paused bot
  game would be stranded until the 1 h cleanup aborts it.
- Web can pause bot games only because PlayComputer resumes them client-side from the
  saved state (`PlayComputer.js:1556`); Android has no such path.
- Leaving it `active` is safe: Home "Continue playing" (`games/active`) reopens it in
  PLAYING, and `games:cleanup-abandoned` eventually aborts it with `result='*'`,
  never a loss.

Finding while checking this: `MonitorGameInactivity.php:85` calls
`$gameRoomService->pauseGame($game->id, 'inactivity')`, but the signature is
`pauseGame(int $gameId, int $pausedByUserId, string $reason = ...)`. Reproduced on
PHP 8.2.27: `TypeError: Argument #2 ($pausedByUserId) must be of type int, string
given`. The command catches and logs it, so the 70 s inactivity auto-pause never
fires for any game. Not changed here (it would alter behaviour for every live game);
recorded as a TODO. If it is ever fixed, casual bot games must be excluded or given a
resume path, or they will be stranded as above.
