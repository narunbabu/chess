# 2026-09-15 09:59 — Web: sent panel on a fresh load with your own resume request pending

## Problem
Found during the 09:50 live check (docs/updates/2026_09_15_09_50_update.md, step 2).
Opening a paused game the lobby way (`lastInvitationAction=resume_game`) while
your own resume request is still pending: the auto-send pre-check
(`GET websocket/games/{id}/resume-status`) answered `pending:true, type:'sent'`
and the client only skipped the send. Nothing populated `resumeRequestData`, so
the overlay fell back to "⚠️ Auto-resume may have failed … Manual Resume Request".

## Change
- `chess-frontend/src/utils/resumeRequestRefusal.js`: new pure helper
  `sentResumeStatusSeconds(status, nowMs)` — seconds left on our own pending
  request from the resume-status body (`expires_at`), 0 for received / none /
  expired / unparsable.
- `chess-frontend/src/components/play/PlayMultiplayer.js` (lobby auto-send
  effect, `type === 'sent'` branch): when seconds > 0, set
  `resumeRequestData {type:'sent'}`, `isWaitingForResumeResponse` true and
  `startResumeCountdown(seconds)` → "📤 Resume request sent from lobby!" +
  "Waiting for opponent to accept… Ns" + Cancel. At 0 the existing countdown
  expiry clears the panel. If the request expired between the server check and
  now, it falls through and sends a fresh request. `startResumeCountdown`
  (stable `useCallback([])`) added to the effect deps.
