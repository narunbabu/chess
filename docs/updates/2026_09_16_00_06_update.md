## 2. Blocker found and fixed — the upload keystore path had gone stale

`chess99-android/keystore.properties` pointed `storeFile` at
`C:/ArunApps/_keystores/chess99-upload.jks`. **That directory does not exist on this
machine** — the keystore is at `D:/ArunApps/_keystores/chess99-upload.jks`. The
project moved from `C:\ArunApps` to `D:\ArunApps` (CLAUDE.md examples still show the
old path) and this pointer was left behind.

This mattered because the release buildType only asks whether `keystore.properties`
*exists*, never whether the `.jks` it names resolves. So the drift would not have
surfaced until deep inside the signing task, on the day of the upload.

Verified the key at the D: path is the right one before changing anything, read-only
via `keytool -list -v`:

| Field | Value |
|---|---|
| Alias | `chess99-upload` |
| Created | 10-Jul-2026, valid to 25-Nov-2053 |
| SHA-1 | `39:87:25:23:36:1A:E8:75:4F:84:B4:7B:8B:9E:40:69:4C:CD:1B:C7` |
| SHA-256 | `72:B3:BB:F1:…:E0:F5:C6:1F` |
| Sig alg | SHA384withRSA |

The SHA-1 matches the upload-key fingerprint recorded in STATUS.md (the GCP OAuth
client item) and the SHA-256 matches `docs/reviews/2026-07-26-android-production-readiness.md` §4.
The recorded `storePassword` opens it and the alias is present.

**Change made:** the `storeFile` line only, `C:/` → `D:/`. Passwords and alias were
not read out, printed or modified; a diff of every other line confirmed byte equality
before the backup was removed. `keystore.properties` is gitignored
(`chess99-android/.gitignore:2`), so this is a local-machine fix and no signing
material enters git.

## 3. Hardening so this class of failure cannot reach an upload

`:app:verifyReleaseConfiguration` checked Firebase, `GOOGLE_SERVER_CLIENT_ID` and
`WS_KEY_RELEASE`, but **nothing about signing**. Added four checks
(`app/build.gradle.kts`): `keystore.properties` present; `storeFile` non-blank;
`storeFile` actually exists on disk; `storePassword`/`keyAlias`/`keyPassword` non-blank.
Without them a missing keystore yields an unsigned bundle that Play rejects only
*after* upload.

Mutation-checked, per this repo's convention — with `storeFile` temporarily pointed at
`Z:/nonexistent/…`, the gate reported the new issue alongside the Firebase one:

```
- app/google-services.json is still the placeholder config. ...
- keystore.properties storeFile does not exist: Z:/nonexistent/ArunApps/_keystores/chess99-upload.jks.
```

`keystore.properties` was restored immediately afterwards and re-confirmed to read
`storeFile=D:/ArunApps/_keystores/chess99-upload.jks`.

Re-run on the corrected tree — **no signing issues, one issue left**:

```
Release configuration is incomplete:
- app/google-services.json is still the placeholder config. FCM, Crashlytics, and Analytics would be inert.
```
