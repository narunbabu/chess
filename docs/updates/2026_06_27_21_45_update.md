# 2026-06-27 — Android app: web feature-parity pass

Audited the Chess99 Android app (`chess99-android`, Kotlin/Compose) against the web
frontend and built the missing **user-facing** functionality so the two stay at parity.

Result: `:app:compileDebugKotlin` **BUILD SUCCESSFUL**. Changes are in the working tree,
**not committed** (commit/deploy on request only).

## Parity gaps closed

1. **Daily-challenge tracks** — `TutorialApi.getDailyChallenge(track)`; ViewModel parses
   `available_tracks` + `access.is_locked`; screen adds track chips and a tier-locked
   "View Plans" upgrade card. (`presentation/daily/`)
2. **Become-Ambassador application** — `ReferralApi.applyAmbassador` / `getAmbassadorApplication`
   (`POST /ambassador/apply`, `GET /ambassador/application`); new `BecomeAmbassadorScreen`
   form (name, mobile, UPI, reason); enrollment banner + status in `AmbassadorDashboardScreen`.
3. **Organization management** — new `OrganizationApi` (+ `NetworkModule` provider): create,
   members, invite, accept/reject. `OrganizationsScreen` gains a Create FAB + dialog, a
   members bottom sheet, and an invite dialog (backend enforces admin permission).
4. **Tournament management** — `ChampionshipApi` adds generate-full-tournament,
   schedule-next-round, submit-result; `ChampionshipDetailScreen` shows an **Organizer
   controls** card (Generate pairings / Schedule next round / Start tournament) gated on
   `canManage` (`created_by == TokenManager.getUserId()`).
5. **Guest play** — "Play as Guest" on `LoginScreen` → `PlayComputer`. Routes are not
   auth-gated and `PlayComputerViewModel` is fully local (native Stockfish), so guests play
   vs the computer with no backend dependency.

## Deliberately deferred (web / WebView, not native)

- Platform-admin analytics dashboards (admins manage from the web).
- Ambassador A4 printable poster (print/desktop surface).
- Native interactive e-book — e-book/privacy/terms already render through `WebViewScreen`
  for content parity.

## Notes

- **Kotlin block comments nest** (unlike Java): a `/*` inside a KDoc — e.g. a path written
  as `organizations/*` — opens an inner comment that eats the real `*/`, yielding
  "Unclosed comment". Avoid literal `/*` in doc comments.
- Build (PowerShell mandatory):
  `powershell.exe -Command "cd 'C:\ArunApps\Chess-Web\chess99-android'; cmd /c 'gradlew.bat :app:compileDebugKotlin --console=plain'"`
