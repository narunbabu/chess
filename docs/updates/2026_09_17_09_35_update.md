# 2026-09-17 09:35 — Public game viewer: orientation, details, share, Play CTA

Closes the P2 follow-up from `2026_09_16_17_30_update.md`: the Android public
viewer always drew White at the bottom (`publicShow` sent no `player_color`)
and had no date/move detail, share, or Play/sign-up CTA.

## Changes

- **Backend** `GameController::publicShow` now returns `player_color`
  (`white`/`black`): the game's stored `player_color` (the human's side in
  computer games); if that is empty and only the black seat has a user,
  `black`; otherwise `white`. Additive field — the web `GameReplayPage` ignores it.
- **Android** `PublicGameViewerScreen.kt`:
  - The board starts from `player_color`, and a new top-bar **Flip board** action
    toggles it (`State.isFlipped` / `bottomColor`).
  - A **details card** shows the date played (localized `played_at`), moves,
    how it ended (`end_reason`), opening and time control. A row is left out
    when its field is missing, and null JSON fields no longer throw (`result`
    used `asString` on a possible JsonNull).
  - A top-bar **Share** action opens the system share sheet with
    `"<white> vs <black> on Chess99\nhttps://chess99.com/games/{id}/replay"`,
    which is the URL the web replay page shares.
  - A **Play CTA card** ("Start playing") goes to `PlayComputer`. That screen
    works for guests (the same target as Onboarding's "Play as guest"), so the
    CTA works whether or not the reader is logged in.
  - 12 new strings in `values/strings.xml`. `NavGraph.kt` wires up `onPlay`.
