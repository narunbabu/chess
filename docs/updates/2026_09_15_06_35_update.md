# 2026-09-15 06:35 — championship_participants.dropped: schema decided, and the forfeit side it records

## Problem
`CheckExpiredMatchesJob::dropPlayerFromChampionship` (reached when a player hits the 2-forfeit limit) did two
things wrong:

1. `$participant->update(['dropped' => true])` — `championship_participants` has no `dropped` column and it was
   not fillable, so Eloquent discarded the attribute silently. The player's remaining matches were forfeited but
   the participant row was never marked, so the next Swiss round or elimination bracket could pair them again.
2. The loop that forfeits their remaining matches always wrote `result_type = FORFEIT_PLAYER1`. When the dropped
   player sat as **player2** the stored result claimed player1 forfeited, contradicting `winner_id` — and
   `StandingsCalculatorService::getMatchResult()` reads `result_type`, not `winner_id`, for forfeits, so the
   recalculated standings gave the **win to the dropped player** and a **loss to their innocent opponent**
   (reproduced: see the mutation check below).

## Schema decision
New nullable columns on `championship_participants` (migration
`2026_09_15_000000_add_dropped_to_championship_participants.php`):

| column | type | meaning |
|---|---|---|
| `dropped_at` | `DATETIME NULL` | when the player was removed from play; `NULL` = still in |
| `dropped_reason` | `VARCHAR(64) NULL` | why, e.g. `forfeit_limit` |

plus index `cp_championship_dropped_idx (championship_id, dropped_at)` for the pairing query. No back-fill: a NULL
stamp already means "still in", so every existing row is correct.

Why not the two alternatives:

- **Not a boolean `dropped`** — the timestamp answers the same yes/no question via `whereNull('dropped_at')` and
  additionally records *when*, which is what an appeal or a "dropped after round N" question needs. The model
  keeps `dropped` as a boolean alias (mutator + accessor, the style already used for `is_paid` and
  `registration_date`), so `update(['dropped' => true])` works and now persists.
- **Not a new `registration_status` value** — that column is the registration/payment lifecycle
  (`payment_pending → registered → refunded`, plus `cancelled`) and is driven by the payment state machine.
  Being dropped is orthogonal: the player is still registered and paid. Folding it in would have mixed it into
  refund handling and `scopeActive()`, whose `cancelled`/`refunded` values also null `active_unique_key` — which
  would let a player dropped for forfeits re-register into the same championship.

## Change
- `database/migrations/2026_09_15_000000_add_dropped_to_championship_participants.php` (new) — columns + index,
  `hasColumn`-guarded, with a reversible `down()` (index first, then columns).
- `app/Models/ChampionshipParticipant.php` — `dropped`/`dropped_at`/`dropped_reason` fillable, `dropped_at` cast,
  `dropped` appended; `setDroppedAttribute()` (idempotent stamp; `false` clears stamp and reason),
  `getDroppedAttribute()`, `scopeDropped()`, `scopeNotDropped()`, `isDropped()`, `markAsDropped(string $reason)`.
- `app/Jobs/CheckExpiredMatchesJob.php` — drops via `markAsDropped('forfeit_limit')`; each remaining match now
  records `FORFEIT_PLAYER1` or `FORFEIT_PLAYER2` according to which side the dropped player occupies, and a bye
  row (`player2_id` NULL) is completed with no winner and no standings credit instead of awarding a win to NULL.
- `app/Services/SwissPairingService.php` — `getEligibleParticipants()` excludes dropped players on both paths
  (the test-tournament / admin bypass that returns everyone, and the paid filter).
- `app/Services/EliminationBracketService.php` — same for the paid bracket entry, and `getSwissQualifiers()`
  (which reads standings, where a dropped player's Swiss score still sits) skips dropped users.

## Notes (not changed — candidates for follow-up)
- The dropped player gets no `loss` recorded for the matches the drop forfeits; only the opponent's `win` is
  added. `processPlayerForfeit` does credit both sides, so standings are inconsistent between the two paths.
- Participant *counts* still include dropped players: `hasEnoughParticipants()`, `hasEliminationWinner()` and
  `scheduleMatchesWithTimeWindows()` in `MatchSchedulerService` / `GenerateNextRoundJob` /
  `AutoGenerateRoundsCommand` filter on payment only, so a championship can stay "in progress" on players who
  are out.
- `ChampionshipRoundType::ELIMINATION` does not exist (see above) — elimination brackets cannot be generated at
  all today.
- Nothing surfaces the drop to the UI; `dropped` is appended to the participant JSON, but no frontend or Android
  screen reads it yet.
