## The options (copy-paste per choice)

### Option A — no deploy on push (recommended; matches the prepared state)

Push as-is; the `[skip ci]` head suppresses `deploy.yml`. Deploy stays manual.

```
git push origin master
gh run list --workflow=deploy.yml --limit 1   # expect: no new run; latest still 34764068752
```

Afterwards the owner can deploy manually (order matters — rotate the CI key
first, or CI stays broken):

```
scripts/rotate-ci-deploy-key.sh --dry-run   # then run it for real (owner-only)
ssh -i ~/.ssh/narun_vps_ed25519 narun@69.62.73.225 'bash -s' < scripts/vps-deploy-step1.sh
ssh -i ~/.ssh/narun_vps_ed25519 narun@69.62.73.225 'CHESS99_SKIP_FRONTEND=1 bash -s' < scripts/vps-deploy-steps2-7.sh
```

### Option B — deploy fires on this push (only viable AFTER key rotation)

With the 2025-10-02 `SERVER_SSH_KEY` this just adds another failed run. Only
choose this after rotating the key. Do **not** `git reset --hard` to drop the
`[skip ci]` heads — it would wipe the uncommitted working-tree edits; add an
empty non-skip head instead:

```
scripts/rotate-ci-deploy-key.sh --dry-run   # then run it for real (owner-only)
git commit --allow-empty -m "chore: deploy master"
git push origin master                      # fires deploy.yml at the new head
gh run watch                                # the pushed daf9405 workflow (sudo as narun) runs untested live — watch it
```

### Option C — check-only CI validation first (safest full-CI path)

Rotate, push as-is (no deploy), then dispatch the check-only run that `daf9405`
introduces (the `-f check_only=true` input is rejected before the push lands):

```
scripts/rotate-ci-deploy-key.sh --dry-run   # then run it for real (owner-only)
git push origin master
gh workflow run deploy.yml --ref master -f check_only=true
gh run watch
```

Going fully manual-by-dispatch permanently (removing the `push:` trigger) would
be a later workflow edit, decided after the first green run.
